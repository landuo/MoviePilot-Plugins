# 稀缺保种

面向 MoviePilot V2 的 RSS 驱动保种插件。插件读取目标站 RSS，通过 IYUU 查询同源种子，
再从 MoviePilot 已配置的来源站取得实时做种人数。手动模式会先展示候选列表，只有用户确认后
才下载来源种子；下载完成后等待已安装的 IYUU自动辅种插件扫描。

也可在候选列表选择“保种站点 · 原种直下”。原种仅支持手动选择，不受跨站来源的最少做种人数和
促销筛选限制；没有跨站匹配、来源被筛选或 IYUU 暂时不可用时仍可选择。下载前会重新获取原种并
验证目标 Hash，遵守同时下载上限，复用下载器中已存在的原种。原种下载完整且下载器已进入做种状态后
标记“保种成功”，无需等待 IYUU 再次辅种；促销和下载流量以原站为准。

工作台中的目标种子和来源候选均提供站点详情页入口。目标种子同时展示目标站的实时做种数、
下载数、完成数和资源大小；详情链接会移除 Passkey、Token 等敏感查询参数后再返回前端。

IYUU 接口负责返回跨站种子映射，不提供实时做种人数。插件取得映射后，优先用“站点＋该站种子 ID”
读取详情：馒头使用详情 API，NexusPHP 类站点解析详情页；每个 ID 一次请求，同站重复 ID 复用结果。
不同来源站并发、同一站点串行，沿用站点 Cookie、API Key、UA、代理、超时和宿主流控检查。
做种数、下载数、完成数及促销从详情读取；页面标明“按 ID 查详情”或“搜索补全”。
只在站点未适配、详情入口/页面结构无法识别、必要字段不完整时使用关键词搜索兜底。
认证、网络、限流失败不追加多次搜索，进入已有的退避重试流程。

兜底搜索优先使用“片名＋季度”（电影使用“片名＋年份”），再使用片名，并在未命中时有限翻页，
完整发布名仅作最后兜底。每个关键词最多查 3 页，每站每条任务最多 8 次搜索请求，
找到全部 IYUU 种子 ID 后立即停止，空页或重复页不再翻页；仍严格按种子 ID 和下载时的 Hash 校验，
不会把同名但不同版本的资源当作同源种子。达到分页上限会明确提示，不宣称站点没有资源。
翻页中途请求失败时保留此前已经找到的候选。

详情获取失败不会删除 IYUU 已知候选，显示“IYUU 已收录 · 详情未获取”和失败原因，支持站点/未知促销筛选。
这类候选不参与自动下载或手动选择；重新匹配取得信息后再按原有下载规则判断。
促销未知不会猜成免费；NexusPHP 仅解析本种标题区促销，不把推荐种子的免费或“审核通过”的样式当作免费。
馒头下载仍使用宿主动态下载链接机制，用户确认下载前不请求下载令牌，下载后继续核验 IYUU Hash。

升级不会对全部历史记录自动重扫，也不会自动下载；漏检旧记录可点击“重新匹配”更新。
IYUU 没有返回映射仍表示“未收录或无已知匹配”，不能据此断言所有站点都没有同源资源。

## 当前 RSS 与历史记录

- 当前 RSS：各订阅最近一次成功拉取的列表中仍存在的种子记录。
- 历史记录：已经移出 RSS 的种子记录，保留候选、下载状态以及原有操作入口。

MoviePilot 侧栏仅保留“稀缺保种”入口，当前 RSS 和历史记录通过工作台内的页签切换。两页独立分页，每页 20 条，
不再受“只显示最近 100 条”限制；记录展示首次发现、最近 RSS 出现和移入历史的时间。
保留全部当前及运行中任务，以及最近 1000 条其他历史记录。

两类记录共用筛选栏，支持任务状态、原站促销、跨站促销（均可选免费 / 非免费 / 未知）、
原站做种人数范围和跨站候选站点。多个条件同时满足才显示，
点击“筛选”应用，点击“重置”清空；切换页签、翻页及自动刷新均保留已应用条件。
先筛选本列表的全部记录再分页，统计卡显示筛选后的数量，页签计数保留未筛选的总数。
条件留空表示不限；人数范围包含边界，`0` 表示零人，人数未知的记录不匹配人数范围。
候选站点匹配 IYUU 已知的跨站来源，包括被下载规则排除或详情未获取的来源，不包含原种。
旧版仅保存了站点、种子 ID/详情页的探测记录也会只读展示，不改写数据库；其下载资格需重新匹配确认。
跨站促销同样依据已有候选；同时选择候选站点和跨站促销时，必须由同一个候选满足。
原站促销与跨站促销独立判断，没有跨站候选的记录不匹配任何跨站促销条件。
应用跨站筛选后，默认选择符合筛选的可用候选，并高亮标注“符合筛选”；原种不会冒充跨站匹配项。
仍可手动改选其他来源，轮询不会覆盖用户选择。筛选不修改后台下载规则或已提交的来源。

## 下载确认与完成判定

手动下载前服务端重新查询来源状态。非免费或未知促销会返回确认信息，页面弹出流量风险确认；
确认后再次核对，下载系数变化时要求重新确认。已有下载器任务直接复用，不重复添加。
自动 / 单候选自动模式仍遵循已配置的促销规则，不使用手动确认弹窗。

弹窗可勾选“后续不再提示下载流量风险”，仅在确认本次最新促销并点击“确认下载”后保存；取消不生效。
该偏好保存在插件配置中，换浏览器或重启后仍生效，适用于所有手动下载（原站、跨站、非免费及促销未知）。
在插件配置开启“下载前提醒流量风险”并保存即可恢复提醒。默认开启，升级不会自动关闭；
关闭提醒不改变站点下载量计算、候选筛选、Hash 校验和同时下载限制，也不会自动选择或下载种子。

99.9% 或 99.95% 不再视为下载完成；校验中、错误、缺失文件也不能提前认定完成。
目标种的数据完整但尚未进入做种状态时显示“数据完整待做种”，暂停及错误另列状态，
不会自动恢复用户暂停的任务。已成功任务也会在后续扫描核对状态，不重复发送相同成功通知。

提交下载器前保存所选 Hash 和提交状态。添加请求异常时显示“下载提交待确认”，只核对同一 Hash，
不会自动切换来源或重复添加；如果下载器始终未出现该任务，需要先人工检查提交结果。

## 后台扫描与异常恢复

手动扫描立即返回，后台执行，进度栏展示下载状态核对、待处理恢复、RSS 拉取、同源匹配、
原站信息更新等阶段及阶段内处理数量。来源查询仍按不同站点并发、同站点串行执行。
扫描时每 5 秒读取进度，空闲时约 15 秒刷新页面；下载器状态仍随扫描核对，不代表每次页面刷新都查询 qB。
扫描期间允许浏览和筛选；下载、重试、忽略仍保持互斥保护，本版未拆分写操作锁。

扫描结果区分成功、部分失败、失败和中断；RSS 拉取全部失败不会显示成功。
已完成的匹配及时保存；重启遗留的“匹配中”任务会在下次扫描恢复。
IYUU / 站点请求异常与真正没有匹配分开处理；单站异常不丢弃其他站点的可用候选。
连续失败采用 5、10、20、40 分钟退避，到期后的扫描才重试；连续失败 5 次停止自动重试，
可手动重新匹配并重置计数。查询和下载均继续遵守原配置的下载模式及限制。

归属由 RSS 内容决定，与下载是否完成无关。种子重新出现在 RSS 时会回到当前页，不重复建任务；
下载中的记录移入历史后仍继续跟踪。多个 RSS 合并判断，只有成功拉取的订阅才更新快照；
网络错误或 RSS 过期时保留该订阅上次成功记录，成功返回空列表则表示该订阅已无种子。
种子匹配和新任务处理上限不影响对已存在记录的归类。

升级前的旧记录暂列历史并标注待确认，下一次成功扫描后自动区分当前和历史。
RSS 快照只保存地址摘要和种子 ID，不保存含 Passkey 的订阅或下载 URL。

## 必要条件

- 已安装并正确配置 `IYUU自动辅种` 插件。
- 使用 qBittorrent，并在两个插件中选择同一个下载器。
- IYUU自动辅种保持启用且配置了执行周期，“辅种站点”包含本插件配置的目标站。
- IYUU自动辅种的“不辅种标签”不要包含 `seed-rescue`。
- IYUU自动辅种开启“沿用原种路径”，不要开启“跳过校验”。

## 严格跳过规则

IYUU 返回的同源站点必须同时满足：

1. 位于配置的来源站列表中；
2. 按 IYUU 的种子 ID 取得有效详情或精确命中的搜索结果；
3. 设置了最少做种人数时，实时做种人数不低于配置门槛；
4. 属于允许的促销类型。

没有任何跨站来源满足条件时，目标种子记为 `SKIPPED_NO_HEALTHY_SOURCE`，不会自动下载，
仍可手动选择保种站点原种。设置了人数门槛时，跨站来源做种人数无法取得按不满足门槛处理。
已精确匹配但未通过下载规则的来源仍展示在表格中，标注做种人数/促销不达标原因，禁用下载选项；
“符合页面筛选”不代表符合后台下载规则。自动模式与单候选自动模式只计算通过下载规则的来源。

## 数值限制

“同时下载数”“最少做种人数”“每个 RSS 单次处理上限”留空或填写 `0` 均表示不限制，
保存后以空值保留，不会自动回填成默认数字；已有配置明确填写的正整数保持不变。
不限制最少做种人数时，人数为 0 或未知的精确匹配来源也可进入候选，但仍遵守来源站点和促销筛选。
不限制单次处理条数时，会处理该 RSS 的全部新种子，并补查所有到期的原站信息；
站点请求并发、同站点串行搜索及失败重试间隔不变，防止同时发起过量请求。
目标站点、RSS、下载器和来源站点等必要配置仍须填写，促销选择规则不变。

## 促销分类

- 免费：下载系数等于 `0`，包括双倍上传免费。
- 非免费：下载系数大于 `0`，包括普通、50%、30% 等。

免费和非免费可以单选，也可以同时选择；促销只作为人数相同时的次级排序条件。

原站促销缺失的旧记录优先补查，此后按上次检查时间轮换刷新；当前与历史记录都参与，
每轮遵守“每个 RSS 单次处理上限”（留空或 0 时不限条数），原站查询最多两路并发，
不再固定刷新 RSS 开头的记录。
成功查询至少间隔 30 分钟，查询失败至少间隔 1 小时，避免同一条失败记录持续占用名额。
搜索失败或促销字段缺失不会覆盖最后一次有效促销，页面展示最近确认时间及本次失败原因；
历史记录缺少原站种子 ID 时会明确提示，不能仅按相似标题猜测促销，更不会默认按免费处理。

## 来源选择模式

- 手动选择：扫描只生成候选列表，用户在工作台选择来源后下载，默认使用此模式。
- 自动选择：按做种人数从高到低自动选择可用来源。
- 仅一个候选时自动：只有一个健康来源时自动下载，多个来源时等待用户选择。

候选首先按实时做种人数从高到低排列；人数相同时优先免费种子，再按配置中的来源站顺序排列。
保种站点原种固定展示在跨站候选之后，不参与自动选择或单候选自动模式的计数。

## 安全说明

RSS URL 通常包含 Passkey。插件任务记录使用 URL 的 SHA256 标识，详情页不会展示完整
RSS URL。MoviePilot V2 的 RSS 帮助类在请求错误时可能把原始 URL 写入系统日志，建议限制
日志访问权限。插件不会自动删除任何来源或辅种数据。

下载任务只添加统一的 `seed-rescue` 标签，不再创建 `seed-rescue-<Hash前缀>` 标签。
任务关联继续使用持久化的目标/来源 InfoHash；下载数量统计仍按统一标签进行，不依赖独立任务标签。
